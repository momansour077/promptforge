# PromptForge v1.1 Roadmap

## Goal

Make PromptForge reliably turn a weak, short, or ambiguous idea into a professional, model-ready prompt in English or Arabic with:

- high prompt quality
- low latency
- clear user trust
- measurable regression protection

The core product promise for `v1.1` is:

> A user types a few words. PromptForge returns a polished, structured, execution-ready prompt that another strong AI model can use immediately.

## Current Baseline

As of `2026-04-26`, the app is already strong in three areas:

- deterministic builder-first generation keeps normal prompt latency low
- English and Arabic prompt quality is validated through the real frontend
- prompt outputs are structured, model-aware, and largely free of meta leakage

Validated benchmark assets:

- frontend multiline suite: `apps/frontend/e2e/frontend-ui-validation.spec.js`
- frontend short-input enhancement suite: `apps/frontend/e2e/prompt-enhancement-short-inputs.spec.js`
- latest reports:
  - `/tmp/promptforge-ui-validation.json`
  - `/tmp/promptforge-ui-enhancement.json`

## Product Principles

`v1.1` should follow these rules:

1. Prompt quality is the product.
2. Short-input enhancement matters more than feature count.
3. Builder-first beats slower AI rewriting unless measured quality clearly improves.
4. Arabic is first-class, not a fallback.
5. Every quality claim should be benchmarked through the real frontend, not just backend tests.

## Priorities

### P0: Must Ship

#### 1. CI quality gate for prompt benchmarks

Why:

- this is the highest-value protection for the product
- prompt regressions are more dangerous than ordinary UI regressions

Deliverables:

- run `npm run test:e2e`
- run `npm run test:e2e:enhancement`
- fail CI on prompt-quality regressions
- archive benchmark JSON as CI artifacts

Impact:

- very high

Effort:

- medium

Success metric:

- no prompt-quality regressions reach `main` without being caught automatically

#### 2. Rename `GENERAL` to `Auto` in the UI

Why:

- users should feel they are using intelligent routing, not backend enums
- `GENERAL` is implementation language, not product language

Deliverables:

- `Target AI: Auto`
- `Prompt Type: Auto`
- visual indicator when manual overrides are active

Impact:

- high

Effort:

- low

Success metric:

- fewer confused manual-override generations

#### 3. Prompt variants after generation

Why:

- users often want refinement, not regeneration from zero
- this increases usefulness without changing the app’s core workflow

Deliverables:

- variant actions:
  - `Sharper`
  - `More technical`
  - `More concise`
  - `More executive`
  - `More creative`
- keep variants deterministic where possible
- save chosen variant in history

Impact:

- very high

Effort:

- medium

Success metric:

- increased reuse from generated prompts instead of repeated fresh generations

#### 4. Ambiguity resolver for very short inputs

Why:

- weak prompts like `pricing`, `coffee ad`, or `kids app` benefit from one fast clarification step
- this improves output quality more than generic over-expansion

Deliverables:

- optional quick chips after very ambiguous input:
  - audience
  - goal
  - format
  - target AI
- keep it lightweight, not a long form

Impact:

- high

Effort:

- medium

Success metric:

- stronger quality on the weakest `1-3` word inputs

### P1: High Value

#### 5. Prompt quality explanation panel

Why:

- users need confidence that the app improved their input
- this helps trust without exposing chain-of-thought

Deliverables:

- short explanation block:
  - what was clarified
  - what assumptions were made
  - why the prompt is stronger

Impact:

- medium-high

Effort:

- low-medium

Success metric:

- improved perceived trust and clarity

#### 6. Domain overlays expansion

Why:

- the next quality gains come from better domain depth, not more generic prompt scaffolding

Target overlays:

- coding
- business
- research
- image generation
- education
- marketing

Deliverables:

- stronger domain-specific role/objective/task/deliverable patterns
- benchmark expansion per domain in both English and Arabic

Impact:

- very high

Effort:

- medium-high

Success metric:

- improved benchmark scores on varied prompt families

#### 7. Better history intelligence

Why:

- good prompts become reusable assets

Deliverables:

- search by domain
- search by target AI
- search by language
- save as reusable template
- duplicate and edit

Impact:

- medium

Effort:

- medium

Success metric:

- higher repeat use of saved prompts

### P2: Performance and Scale

#### 8. Frontend bundle reduction

Why:

- generation is already fast
- remaining performance pain is frontend load, especially larger deferred chunks

Deliverables:

- reduce `SettingsPage` weight
- defer `recharts`
- trim the large textarea/editor path
- measure first-load improvements

Impact:

- medium-high

Effort:

- medium

Success metric:

- better first-load and route-load timings without harming UX

#### 9. Real user prompt feedback loop

Why:

- benchmark quality matters, but real usefulness matters more

Deliverables:

- user feedback on generated prompt:
  - worked well
  - needed edits
  - too vague
  - wrong direction
- optional “used in ChatGPT/Claude/Gemini/etc.”

Impact:

- high

Effort:

- medium

Success metric:

- real-world guidance for improving the builder where users actually struggle

## Success Metrics

Track these in `v1.1`:

- prompt benchmark pass rate in CI
- average frontend generation time for builder-first prompts
- average short-input expansion ratio
- percent of prompts regenerated vs refined through variants
- percent of prompts saved / favorited / reused
- English benchmark score
- Arabic benchmark score
- first-load frontend performance

## What Not To Do In v1.1

Avoid these unless benchmarks justify them:

- reintroducing slow remote rewriting as the default path
- adding broad multi-model orchestration before prompt quality feedback exists
- overcomplicating the input form
- adding many weak “AI magic” features that do not directly improve prompt outcomes

## My Recommendation

If only three things ship next, they should be:

1. CI quality gate for prompt benchmarks
2. Prompt variants
3. Ambiguity resolver for short inputs

That combination best improves:

- trust
- prompt quality
- user control
- regression safety

while keeping the app focused on its strongest value proposition.
